# 🤝 Contributing to Enterprise SIEM

Thank you for considering a contribution to our SIEM project! We welcome contributions from the community to help make this project better. Please take a moment to review this document to understand our contribution process.

## 📌 Contribution Process

1. **Fork the Repository**  
   Create your own fork of the repository to work on changes.

2. **Create a Feature Branch**  
   ```bash
   git checkout -b feature/your-feature-name
   ```

3. **Make Your Changes**  
   Implement your changes following the coding standards.

4. **Test Your Changes**  
   Ensure all tests pass and add new tests if necessary.

5. **Commit Your Changes**  
   ```bash
   git commit -m "Fix: your commit message"
   ```

6. **Push to Your Fork**  
   ```bash
   git push origin feature/your-feature-name
   ```

7. **Open a Pull Request**  
   Submit a pull request to the main repository with a clear description of your changes.

## 🧱 Code Standards

- **Branch Naming Conventions**
  - Feature branches: `feature/your-feature-name`
  - Bug fixes: `fix/issue-description`
  - Documentation: `docs/documentation-topic`

- **Commit Message Guidelines**
  - Use imperative mood (e.g., "Fix bug" not "Fixed bug")
  - Keep messages concise and descriptive
  - Reference issues with `#issue-number`

## 🧪 Testing Requirements

All contributions must include appropriate testing:

- Unit tests for new functionality
- Integration tests for major changes
- Validation of Sigma detection rules
- Documentation updates for any feature changes

## 📚 Documentation Contributions

Help us improve our documentation by:
- Keeping content clear and concise
- Using consistent terminology
- Including relevant examples
- Following the documentation style guide

## 🛡️ Security Contributions

We welcome contributions to improve our security features:
- New detection rules (Sigma format)
- Threat intelligence integration
- Compliance framework enhancements
- Security hardening measures

## 📖 Style Guide

- Use consistent markdown formatting
- Keep paragraphs short and focused
- Use code blocks with appropriate language specification
- Include diagrams where they add value

## 📝 Review Process

All contributions will go through:
1. Automated validation (linting, tests)
2. Peer review by maintainers
3. Security review for relevant changes
4. Final approval and merge

## 🤝 Community Guidelines

We expect all community members to follow our [Code of Conduct](CODE_OF_CONDUCT.md). Please report any unacceptable behavior to security@company.com.

## 📢 Getting Help

If you have questions or need help with your contribution:
- Join our Slack workspace (#siem-dev channel)
- Attend our weekly contributor meetings
- Review our contributor documentation

Thank you for your contributions to make our SIEM system better!
